## 1. 先修正一个预期（很重要）

我之前说过「BC 大概率打不过那 10 行反馈控制」。**这个说法要修正，原因是我没算清楚这个任务的特殊性。**

**FetchReach 的反馈专家是 `a = clip(k·(goal − pos), −1, 1)` —— 这是一个线性函数（除了 clip 边界）。**
而 BC 的输入里，**第一项正好就是 `goal − pos`**。

> **所以 BC 要学的东西，本质上是 `a = k·x`，一个线性映射。**

指南 7.2 节原话：

> 「若专家本身近似线性，线性回归可能已经足够；**复杂网络没有优势是合理结果**。」

**所以正确的预期是**：

| 情况 | 结论怎么写 |
|---|---|
| BC ≈ 反馈专家（成功率接近） | ✅ **正常**。说明"在当前任务中，专家策略是线性的，BC 用 MLP 没有额外收益" |
| BC 略低（差 1–3 个回合） | ✅ **正常**。clip 边界附近是分段线性，MLP 学不准 |
| BC 明显低（差一半以上） | ⚠️ **不正常**。查数据覆盖、训练/推理一致性、归一化 |

**三种情况里没有一种是"BC 一定输"或"BC 一定赢"。**
**你唯一不能做的是：为了让 BC 赢而挑种子。** 指南第 12 周原文：「不要为了得到单调曲线而挑选训练种子」。

> **所以这周真正要验证的，不是"学习比控制好"，而是"我能不能把一个对照实验做干净"。**
> 这个能力比结论重要一百倍。

## 2. 这周最大的数学事实：一定过拟合

先把这个算清楚，否则你会误以为模型写错了。

**你的数据量**：20 条轨迹 × 50 步 = **最多 1000 个样本**（FetchReach 每回合跑满 50 步，不会提前终止）。

> **⚠️ 但这个 1000 是上界，不是有效样本数。** 反馈专家大概 8–12 步就到目标，
> 剩下近 40 步都是"已经在目标、动作为 0"的静止样本。
> **有效样本可能只有 150–250 个。** 真实数字要在 D1 的 A1.1 里测出来。

**你的模型参数量**（2 层隐藏层 × 128，输入 8 维，输出 3 维）：

```
第 1 层：8×128 + 128 = 1,152
第 2 层：128×128 + 128 = 16,512
输出层：128×3 + 3 = 387
────────────────────────────
合计：18,051 个参数
```

**1000 个样本训 18,051 个参数 = 1 : 18；如果有效样本只有 200 个，就是 1 : 90。**

> ## 过拟合是数学必然，不是 bug。

**所以有三件事不是"可选"，是"必须"**：

1. **必须按验证集 loss 选 checkpoint** —— 用最后一个 epoch 一定更差
2. **训练 loss 一定会降到接近 0**，这不能证明任何事
3. **验证 loss 会先降后升** —— 升的那个点就是该停的地方

**你要看的唯一曲线是验证集那条。** 训练集那条降得再漂亮也没有信息量。

> **如果 D1 测出静止样本占比 > 30%**，按 A1.1 的规则加权；
> **如果时间宽裕**（W5 提前完成说明 6h/周是够的），把轨迹加到 **40 条**，
> 然后做 **20 vs 40 的规模对照** —— 这正是指南第 12 周「数据规模与简单基线」要的东西。
> **加轨迹比加模型有价值得多。**

而 BC 的输入第一项就是 `desired_goal − achieved_goal`，每一步的 `dist` 也要用它算。

| 结果 | 处理 |
|---|---|
| 有 `desired_goal` | 直接往下 |
| **没有 `desired_goal`** | **花 10 分钟重采一遍**（20 回合几秒钟），把 `desired_goal` 加进字段 |

> **为什么必须重采而不是"想办法凑"**：`desired_goal` 是 `env.reset()` 时随机采样的，
> **事后完全无法恢复**。没有它，这批轨迹对 BC 就是废数据。
>
> **好消息是重采极便宜** —— 20 回合、每回合 50 步，纯 CPU 几秒钟。
> 这也说明：**采集脚本的字段清单要在写之前想清楚，漏一个就得重来。**

#### A1.1 再查四条

W5 的 `data/raw/feedback_seed*.npz` 已经有了。打开一条，确认：

| 检查 | 通过标准 |
|---|---|
| 每条的 `steps` 是 50 | FetchReach 不提前终止，`terminated` 恒 False，`truncated` 在最后一步 True |
| `action` 全部在 [−1, 1] | `np.abs(actions).max() <= 1.0` |
| `achieved_after − achieved_before ≈ 0.05 × action[:3]` | 误差 <1e-6 —— **这条验证动作语义** |
| **「静止样本」占比** | 见下 —— **这条可能推翻整个训练设计** |

**前三条如果对不上，停下来。** 说明 W5 存的动作和你以为的不是一回事，后面全白做。

#### A1.2 第四件事：先统计"到达后停着"的样本有多少

**这是一个真实的设计陷阱，我在复核时才发现：**

`terminated` 恒为 False → **每条轨迹都跑满 50 步**。但反馈专家大概 **8–12 步就到目标**了，
剩下 38–42 步都在目标附近，此时 `error ≈ 0` → `action ≈ 0`。

> **也就是说：约 75–85% 的训练样本是"已经在目标、动作为 0"。**

**BC 会学到什么**：一个永远输出接近 0 的策略。从远处起手时它走不动，闭环成功率会莫名其妙地低。

**先测量，别猜**。跑这几行：

```python
import glob, numpy as np
data = [np.load(f) for f in sorted(glob.glob("data/raw/feedback_seed*.npz"))]

all_a   = np.concatenate([d["action"] for d in data])                 # (N, 4)
all_d   = np.concatenate([np.linalg.norm(d["desired_goal"] - d["achieved_before"], axis=1)
                          for d in data])                             # (N,)
print("样本数", len(all_a))
print("|a| < 0.01 占比", (np.abs(all_a[:, :3]).max(1) < 0.01).mean())
print("dist < 0.05 占比", (all_d < 0.05).mean())
for i, d in enumerate(data[:5]):
    dist = np.linalg.norm(d["desired_goal"] - d["achieved_before"], axis=1)
    first = np.argmax(dist < 0.05) if (dist < 0.05).any() else -1
    print(f"seed {i}: 首次成功步 = {first}，总步 = {len(dist)}")
```

**决策规则（按测出来的数字走）**：

| 静止样本占比 | 处理 |
|---|---|
| **< 30%** | 不用管，直接往下走 |
| **30%–60%** | **给样本加权**：`w = 1.0 if dist > 0.05 else 0.1`，写进 DataLoader 的 `weight` |
| **> 60%** | **加权 + 把轨迹加到 40 条**（20 条有效样本太少，训不动 18k 参数） |

> **加权只需要 3 行代码**，比截断好 —— 截断到"首次成功"会把 1000 个样本砍到 200 个，
> 18k 参数对 200 个样本，过拟合会到没法看的地步。
>
> **这个数字必须写进报告第 3 节。** 它解释了你的 BC 为什么是这个表现。

> **顺带一个好消息**：如果你测出来 `< 30%`，说明反馈专家收敛得慢（k 偏小），
> 那轨迹里"从远处靠近"的样本就多，BC 反而更好学。**k 的选择在这里第二次影响结果。**

### A2 输入输出定义（20min）· 写清楚再写代码

**输入（8 维）**：

| 维度 | 内容 | 来源 |
|---|---|---|
| 0–2 | `desired_goal − achieved_goal` | **相对位置，最重要的一维** |
| 3–5 | `observation[3:6]` = 末端速度 | 本体状态 |
| 6–7 | `observation[6:8]` = 夹爪开合 | 本体状态 |

**输出（3 维）**：`action[:3]`。**抓手通道不预测**，执行时固定 0。

> **指南 7.2 原文**：「策略预测三个移动通道，抓手通道在执行端固定。**这样不会让网络浪费容量去学习一个与任务无关的常量**。」
> **输入字段必须完整列出来** —— 这张表就是要贴进报告的。

**不要输入 `observation[0:3]`**（末端绝对位置）—— 它和 `achieved_goal` 重复，而且绝对位置对"到点"这个任务是冗余信息，加进去只会让模型更难学。
**除非你要做对照实验**，那就单独跑一组，别混在一起。

### A3 划分：按回合，不按样本（15min）

```python
# 正确：按回合划分
train_seeds = list(range(0, 15))     # 15 条训练
val_seeds   = list(range(15, 20))    # 5 条验证

# 错误（千万别这么写）：
# 把所有样本打乱后 80/20 切分
```

> **为什么按样本切分是错的**：同一回合相邻两帧的观测几乎一样（只差 0.05 m 的位移）。
> 随机切分会把"几乎相同的帧"分到训练和验证两边 → **验证 loss 虚低 → 你以为泛化了，其实只是记住了**。
> 指南第 9 周原文：「把完整回合放进同一集合」；第 2 个自测题就是这个问题。

### A4 Sanity check（35min）· 这周最重要的 35 分钟

**在跑正式训练之前，必须先做这一步：**

> ## 从训练集里取 **32 个样本**，把模型过拟合到训练 loss ≈ 0。

```python
# 只取 32 个样本
x32, y32 = x_train[:32], y_train[:32]
# 训 2000 步，不做任何正则，不划分验证集
# 目标：loss < 1e-4
```

**三种结果，三种含义**：

| 现象 | 含义 | 处理 |
|---|---|---|
| loss 降到 <1e-4 | ✅ 模型、标签、梯度、损失函数全部正确 | 继续 |
| loss 卡在 0.01 附近不动 | ⚠️ 学习率太小，或模型容量不够 | 先调 lr（×10 试） |
| loss 完全不动 / 变 nan | ❌ **标签错位**（`obs_before` 配成了 `obs_after`）、**梯度没回传**、或 **lr 太大** | 停下来查，别往下走 |

> **为什么这一步不能省**：如果连 32 个样本都过拟合不了，说明管线有 bug。
> **后面用 1000 个样本训练，你会看到"loss 不降"但分不清是"数据太难"还是"代码错了"** —— 那就永远查不出来。
> 指南 5.6 节原话：「先用几十个样本检查模型能否把训练误差降到很低，再扩大数据规模。**这个检查用于发现输入标签错位、梯度未更新和模型容量不足**」。

**把这三个数字记进报告**：32 样本、训练步数、最终 loss。这是你"管线正确"的证据。

## B · D2（1.5h）· 正式训练 3 个种子

### B1 归一化：只从训练集算，随模型保存（20min）

```python
# 正确
x_mean, x_std = x_train.mean(0), x_train.std(0) + 1e-8
x_train_n = (x_train - x_mean) / x_std
x_val_n   = (x_val   - x_mean) / x_std      # ← 用训练集的统计量！
torch.save({"model": model.state_dict(), "x_mean": x_mean, "x_std": x_std}, path)

# 错误（数据泄漏）
# x_mean = np.concatenate([x_train, x_val]).mean(0)
```

> **指南 5.6 节原文**：「归一化统计量**只从训练集计算，并连同模型保存**。评估时冻结统计量；
> **不要重新用测试集均值和方差处理输入**。」
>
> **这条错了后果很隐蔽**：验证指标会虚高，闭环测试时你用的是测试集的统计量，而真实部署时没有"测试集统计量"可用 —— **模型直接崩，但你不知道为什么**。

**动作要不要归一化？**
FetchReach 的动作本来就在 [−1,1]，**可以不归一化**。如果你归一化了，**推理时必须反归一化**，而且要用训练集的 `y_mean/y_std`。指南第 10 周原文：「检查动作反归一化、裁剪和数据类型，**避免训练输出与执行接口不一致**」。

**建议：动作不归一化。** 少一个出错的地方。

### C2 测试协议（30min）· 一个字都不能松

| 项 | 要求 |
|---|---|
| 测试回合数 | **20 回合**，`seed = 100..119` |
| 这些种子 | **必须没参与过任何调参**（训练用 0–14，验证用 15–19） |
| 初始条件 | **四个模型面对同一组 seed 100–119** |
| 成功判据 | `info["is_success"]`，即距离 < **0.05 m** |
| 记录 | 成功率（分子/分母）、最终距离、步数、推理延迟、失败分类 |

> **⚠️ 复核发现的一个坑：W5 的基线跑在 seed 0–19 上，W6 的测试是 100–119。**
> **所以 W5 那个"反馈专家 20/20"不能直接搬进 W6 的对照表** —— 初始条件不同，不可比。
>
> **必须在新种子 100–119 上重跑一遍反馈专家和随机策略。** 20 个回合，几秒钟的事，
> 但少了这一步，整张对照表就是无效的。
>
> **指南 8.1 节原文**：「随机策略、控制器和学习策略**尽量面对同一组测试初始条件**。」
> **这句话做不到，整张表就不可比。**

### C3 失败分类（20min）

失败回合**不许删**，按现象归类：

| 类别 | 判据 |
|---|---|
| 走不到位 | 最终距离 > 0.05，且过程中距离在减小 |
| 方向错误 | 最终距离 > 初始距离（越走越远） |
| 振荡 | 距离在 0.05 附近反复穿越，最后停在外面 |
| 超时 | 50 步用完仍未成功 |

**每一类写清有几个回合、是哪些 seed。** 这比"成功率 75%"信息量大得多。

## F · 卡点预案

| 卡在哪 | 处理 |
|---|---|
| 32 样本过拟合不了（loss 卡住） | ① 查标签是不是 `action[:3]` 而不是整个 4 维；② lr ×10 试；③ 打印 `loss.requires_grad` |
| 32 样本 loss 变 nan | lr 太大，降到 1e-4；或输入里有 nan（`np.isfinite(x).all()` 查） |
| 训练 loss 降了但验证 loss 一直升 | **正常，就是过拟合**。按验证集选 checkpoint，报告里写清 |
| 闭环测试成功率 0/20 | ① 推理时忘了 `model.eval()`；② 忘了用训练集的 `x_mean/x_std`；③ 动作忘了 clip |
| 闭环测试越走越远 | 输出符号反了。检查训练标签是不是 `action` 而不是 `−action` |
| 线性回归比 MLP 好 | **正常且重要**。说明专家近似线性、MLP 过拟合了。**照实写，这是有效结论** |
| BC 从远处起手就走不动 | 大概率是**静止样本占比过高**（A1.1 测过）。加权重训，或加轨迹数 |
| 静止样本占比 > 60% | 加权 + 轨迹加到 40 条。**只有 200 个有效样本训 18k 参数，不可能是别的原因** |
| 每条轨迹步数不是 50 | 说明这个版本 `terminated` 会在成功时为 True —— **那更好**，样本天然截断。但要把第 2 章的样本数改掉 |
| 三个种子差异极大（比如 20/20 vs 5/20） | 小样本训练的正常波动。**三个都报，不要只报最好的** |
| 归一化后验证指标虚高 | 你可能用了训练+验证的合并统计量。改成只用训练集 |
| 时间只给到 3h | 保 **sanity check + 训练 1 个种子 + 闭环 20 回合 + 报告的前 4 节**。3 种子改成 1 个并在报告里注明 |
| 时间只给到 2h | 保 **sanity check + 训练 1 个种子 + 闭环 20 回合**。报告顺延到 W7 开头 |
