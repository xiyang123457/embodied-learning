坐标变换与正运动学：把一个点送到它该在的地方

文档说明

这份教程覆盖 W3 的全部内容：变换的方向约定、二维与三维旋转、4×4 齐次变换、四个坐标系之间的关系、二连杆正运动学。目标是能对任何一个变换说清「从哪个系到哪个系」，并且不靠推导就能判断一条乘法链是否合法。

全部内容约 52 分钟，其中包含一次动手验证。

时间 内容 完成标志
0 到 7 分钟 一个找快递的场景 能说出「从 3 栋到信箱」和「从信箱到 3 栋」为什么不是一回事
7 到 19 分钟 T_target_source 命名规则与二维手算 能写出 (1,0) 先转 90 度再平移 1 米的结果，以及反序的结果
19 到 31 分钟 三维旋转、4×4 齐次变换、便宜求逆 能用 R_y(90) 把 sin 符号写反的矩阵抓出来
31 到 41 分钟 四个坐标系、下标消去、二连杆正运动学 能写出算例的合法乘法链，并说出错写法的输出

文中所有数字都在本机实测过，环境为 Windows + Python 3.10.19 + numpy 2.2.6。验证脚本是 scripts/w3_tutorial_check.py。

这份教程不实现四元数、欧拉角旋转顺序、李群李代数。原因写在第四节末尾。它假定你会 Python 和 NumPy，做过点与向量的加减乘。

一、从一个场景开始

快递员把包裹放在 3 栋门口的快递柜里。你从小区大门出发，走了两段：大门到 3 栋，3 栋到快递柜。

每段路都隐含一句话：从哪出发，到哪去。如果你把第二段记成「从快递柜到 3 栋」，你会从柜子往回走，最后站在小区门口发呆。路本身没错，方向反了，结果全不对。

机器人算位置是同一件事。相机看到目标，报告的是「目标在相机坐标系里的位置」。要把它换算到机械臂基座坐标系，就得连走几段，每段都带方向。

日常说话里「3 栋到柜子」和「柜子到 3 栋」几乎没区别，反正都在那片地方。矩阵里这两者差一个转置，换算出来的位置能差好几米。

找快递的环节 具身系统里的对应物 术语
小区大门 机械臂安装的基准坐标系 base
3 栋 机械臂末端坐标系 end
3 栋门口的快递柜 固定在末端上的工具 tool
你手里手机拍的照片 相机画面 cam
照片里的包裹 相机测到的目标 obj
「从大门怎么走到 3 栋」 把 3 栋的坐标变到大门系 T_base_end
「从 3 栋怎么走到柜子」 把柜子的坐标变到 3 栋系 T_end_tool

有一件事要先分开：T_base_end 会随关节角变化，每次都不同；T_end_tool 是装好之后不再变的固定值；T_base_cam 靠标定得到；T_cam_obj 是相机当场测出来的。这四个量性质完全不同，当成同一类东西处理，一定会算错。

二、变换的方向由名字决定

一个旋转矩阵单独看没有方向信息。[[0,-1],[1,0]] 这个矩阵，可以表示「把点逆时针转 90 度」，也可以表示「换一个转了 90 度的坐标系去看同一个点」。两种说法在数值上完全一样。

所以真正需要固定下来的不是矩阵，是命名。规则只有一条：

T_target_source  表示把 source 系里的点，变到 target 系
p_target = T_target_source @ p_source

复合的时候，下标像单位换算那样相邻消去：

T_base_obj = T_base_cam @ T_cam_obj
             └─ base←cam ─┘
                          └─ cam←obj ─┘
             base ←────────────── obj     下标首尾相接，合法

T_cam_base @ T_cam_obj 的下标是 cam←base 和 cam←obj，中间的 base 和 cam 对不上，这个乘积没有几何意义。程序不会报错，它只会给你一个数字。

第五节的算例会看到，错写法给出的结果是 (0, 0, 0)。一个完全合法、看起来像答案、实际上什么都没说的三元组。这类错误最难查，因为输出不是 NaN，也不是报错。

三、二维：把两步压成一个矩阵

取点 p = (1, 0)，先绕原点逆时针转 90 度，再沿 x 方向平移 1 米。

第一步把 x 轴上的点送到 y 轴：(1,0) → (0,1)。第二步在原坐标系里加 1 米：(0,1) → (1,1)。

换成矩阵，旋转和平移本来是两种运算：

p' = R p + t

转两次再移两次，就得写两遍加号。把点升到三维，末尾补一个 1，就能把加号吸进矩阵：

p' = T p ,   T = [[R, t],
                  [0, 1]]

本题的 T 是

T = [[0, -1, 1],
     [1,  0, 0],
     [0,  0, 1]]

T @ (1, 0, 1) 得到 (1, 1, 1)，前两维就是手算的 (1,1)。第三维那个 1 从头到尾不变，它存在的唯一用途就是让平移能被乘进去。

这个第三维也叫齐次坐标。它看起来像个技巧，实际是整个体系能写成连乘的原因。没有它，第四节的下标消去无从谈起。

现在把顺序反过来，先平移再旋转。两个矩阵相乘的顺序变了，结果也变了：

反序 T = [[0, -1, 0],
          [1,  0, 1],
          [0,  0, 1]]

代入 (1,0,1) 得 (0,2,1)，前两维是 (0,2)。同一个 1 米，正序里落在 T[0][2] 即 x 分量，反序里落在 T[1][2] 即 y 分量。旋转块一个字都没变。

写在 R 右边的东西会被 R 一起转，写在 R 左边的东西不会。这就是矩阵乘法不交换的几何含义。

求逆与两个自检

二维旋转的逆就是转置，因为 R 的两列是正交单位向量。平移的逆不是简单取负：

T⁻¹ = [[Rᵀ, -Rᵀ t],
       [0,  1    ]]

写 -t 是这一周最常见的错误。-t 只在对 R 是单位阵时才对。

另外两个自检值得记一辈子。Rᵀ R 应该等于单位阵，det(R) 应该等于 +1。如果 det 算出 -1，那不是旋转，是镜像，说明某个符号错了或者用了行向量约定。

还有一个浮点细节。np.cos(np.pi/2) 等于 6.123e-17，不等于 0。所以所有比较都要用 np.allclose，不能用 ==。

四、三维：R_y 是唯一反着放的那个

三个基本旋转是把二维的 [[c,-s],[s,c]] 往对应轴上搬：

R_x(θ) = [[1,  0,     0    ],   R_y(θ) = [[ cosθ, 0, sinθ],
          [0,  cosθ, -sinθ],             [ 0,    1, 0   ],
          [0,  sinθ,  cosθ]]             [-sinθ, 0, cosθ]]

R_z(θ) = [[cosθ, -sinθ, 0],
          [sinθ,  cosθ, 0],
          [0,     0,    1]]

R_x 和 R_z 里 -s 都在右上角，R_y 里 -s 跑到左下角去了。原因是绕 y 轴转的循环方向是 z→x→z，跟另外两个反着。

自检只有一条：R_y(90°) @ (0,0,1) 应该等于 (1,0,0)，z 轴正方向被转到 x 轴正方向。把 sin 的符号写反，同一个向量会得到 (-1,0,0)。方向差 180 度，误差不是小数级别，但程序照样跑得通。

三维的齐次变换一样是 4×4：

T = [[R, t],
     [0, 1]]

求逆的便宜算法依然是 [[Rᵀ, -Rᵀt], [0,1]]。它比 np.linalg.inv 快，而且因为 R 是正交阵，误差也更小。反过来，T.T 永远不等于 T⁻¹，除非平移恰好是 0。这个差别有多大取决于平移的长度，在本文的算例里是 1.0。

四元数、欧拉角的旋转顺序、李群李代数这三样，这一周只到「知道它存在」为止。四元数要知道不同库的分量排列顺序不同，用之前查文档；欧拉角要知道旋转顺序和奇异位置会带来问题；李群李代数要知道它解决的是「旋转不能直接相减」这件事。指南的原话是不以背完公式作为开始机器人实验的条件。

五、四个坐标系、下标消去与正运动学

一个典型的抓取系统有六个坐标系，关系是一棵树：

world ──► base ──► end ──► tool
                     │
                     └──► cam ──► obj

base 到 end 由关节角决定，这也是唯一随时间变化的边。end 到 tool 是固定值。base 到 cam 靠手眼标定。cam 到 obj 由相机当场测出。

一个能全程手算的算例

相机装在基座右侧 1 米，绕 z 轴转了 90 度，光轴指向基座系的 +y。物体在相机正前方 1 米。末端在 (0.5, 0.5, 0)，姿态与基座一致。

第一步把物体从相机系变到基座系：

T_base_cam = 转 90 度 @ 平移 (1, 0, 0)
T_cam_obj  = 无旋转 @ 平移 (1, 0, 0)

T_base_obj = T_base_cam @ T_cam_obj

相机看到的是自己的 +x 方向，转了 90 度之后在基座系里指向 +y。所以物体在基座系的位置是 (1,0,0) + (0,1,0) = (1,1,0)。

第二步把它从基座系变到末端系，用逆变换：

T_end_obj = inverse(T_base_end) @ T_base_obj

末端没有旋转，平移是 (0.5, 0.5, 0)，所以物体相对末端是 (1,1,0) - (0.5,0.5,0) = (0.5, 0.5, 0)。

这两步都能手算，实际输出和手算完全一致。把第一步写成 T_cam_base @ T_cam_obj，输出变成 (0,0,0)，也就是基座原点。这个数字看起来完全正常，甚至有点像一个「对齐了」的结果，这就是它的危险之处。

二连杆正运动学

正运动学就是「把几条变换连起来」这件事的最简单形态。平面二连杆，杆长 l1 和 l2，关节角 θ1 和 θ2：

x = l1·cos(θ1) + l2·cos(θ1 + θ2)
y = l1·sin(θ1) + l2·sin(θ1 + θ2)

第二项是 cos(θ1+θ2) 而不是 cos(θ2)。写成后者是最常见的错误，因为它看起来更对称。

取 l1 = l2 = 1，四个手算核对值如下，本机实测与手算一致：

θ1 θ2 末端位置 含义
0 0 (2.000000, 0.000000) 完全伸直
π/2 0 (0.000000, 2.000000) 竖直向上
0 π (0.000000, 0.000000) 完全折叠，回到基座
π/4 π/2 (0.000000, 1.414214) 两个 cos 正好抵消

最后一行是最有信息量的自检。45 度和 135 度的 cos 相加等于 0，sin 相加等于 √2。如果算出来不是 (0, 1.414)，角度累加一定错了。

工具偏移则要写成变换乘法而不是位置加法：

T_base_tool = T_base_end @ T_end_tool
T_end_tool  = make_T(I, [0.1, 0, 0])

在 θ1=0, θ2=π 这一组，末端原点回到 (0,0)，但工具尖端在 (-0.1, 0)。因为工具跟着末端一起转了 180 度，伸出去的方向反了。位置和姿态是耦合的，改一个必然改另一个。这就是为什么必须用齐次变换而不是「位置加角度」两套数据。

逆运动学不在本周的实现范围内，但要多解和无解这两个概念值得知道。目标在 (1.2, 0.3) 时，由余弦定理 cos θ2 = (1.44 + 0.09 - 2)/2 = -0.235，θ2 有两个解，±103.59°，分别是肘上和肘下。目标在 (3, 0) 时同样是这个公式给出 cos θ2 = 3.5，超出 [-1,1]，无解，因为那两个长度够不到。

这套东西在真实系统里长什么样

ROS 2 的坐标变换库 tf2 把这条命名规则直接写进了函数签名：

tf_buffer.lookup_transform(target_frame, source_frame, time)

要拿「相机在基座系里的位姿」，写的是 lookup_transform("base_link", "camera_link", t)。两个参数写反，库不会纠正，它老老实实返回另一个方向的变换。

手眼标定是这件事最直接的应用。不管用棋盘格还是 AprilTag，标定程序最后交付的就是一个 4×4 矩阵，也就是 T_base_cam，剩下的事和本文算例完全一样。

scipy.spatial.transform.Rotation 的 as_quat 默认返回 (x, y, z, w) 顺序，一部分库和论文用 (w, x, y, z)。这就是前面说的分量排列顺序问题，它不报错，只让你算出一个转了奇怪角度的姿态。

VLA 模型输出的 action 通常有 7 维：3 维平移、3 维姿态、1 维夹爪开合。本文的二维点就是它的前两维，砍掉了姿态和夹爪。

六、动手验证

下面这段脚本验证三件事，不实现二连杆和工具偏移，那部分是本周 P3 的交付内容。跑完约 1 秒。完整文件在 scripts/w3_tutorial_check.py。

"""W3 原理验证：一个变换的方向由它的名字决定。"""
import numpy as np


def rot_y(t):
    """绕 y 轴转 t 弧度。全篇唯一一个 sin 符号反着放的矩阵（z→x→z 循环）。"""
    c, s = np.cos(t), np.sin(t)
    return np.array([[c, 0.0, s], [0.0, 1.0, 0.0], [-s, 0.0, c]])


def rot_z(t):
    """绕 z 轴转 t 弧度。二维 [[c,-s],[s,c]] 的直接推广。"""
    c, s = np.cos(t), np.sin(t)
    return np.array([[c, -s, 0.0], [s, c, 0.0], [0.0, 0.0, 1.0]])


def make_T(R, t):
    """拼 4x4 齐次矩阵 [[R, t], [0, 1]]。第 4 维把「乘法加加法」压成纯乘法。"""
    T = np.eye(4)
    T[:3, :3] = R
    T[:3, 3] = t
    return T


def inverse(T):
    """便宜求逆 [[Rᵀ, -Rᵀt], [0,1]]。写法错成 -t 是最常见的 bug。"""
    R, t = T[:3, :3], T[:3, 3]
    Ti = np.eye(4)
    Ti[:3, :3] = R.T
    Ti[:3, 3] = -R.T @ t
    return Ti


# ==== 1. R_y 的符号自检 ====
# 绕 y 转是 z→x→z 的循环，所以 z 轴正方向应该被转到 x 轴正方向
wrong_y = np.array([[0.0, 0.0, -1.0], [0.0, 1.0, 0.0], [1.0, 0.0, 0.0]])
print("== 1. R_y 的符号自检 ==")
# round 到 6 位：cos(pi/2) 是 6.12e-17 不是 0，不 round 会盖住真正的分量
print("  R_y(90) @ (0,0,1)   =", np.round(rot_y(np.pi / 2) @ [0, 0, 1], 6))
print("  错符号版 @ (0,0,1)   =", np.round(wrong_y @ [0, 0, 1], 6))

# ==== 2. 下标消去：同一组矩阵，两种乘法 ====
# 相机装在基座右侧 1 m 且绕 z 转 90 度；物体在相机正前方 1 m
T_base_cam = make_T(rot_z(np.pi / 2), [1.0, 0.0, 0.0])
T_cam_obj = make_T(np.eye(3), [1.0, 0.0, 0.0])
right = T_base_cam @ T_cam_obj
# 下标 base←cam 接 cam←obj，中间 cam 消掉，结果 base←obj，合法
wrong = inverse(T_base_cam) @ T_cam_obj
# 下标 cam←base 接 cam←obj，中间对不上，没有几何意义，但程序不报错

print("\n== 2. 下标消去 ==")
print("  T_base_cam @ T_cam_obj =", right[:3, 3])
print("  T_cam_base @ T_cam_obj =", wrong[:3, 3])

# ==== 3. 便宜求逆与转置的区别 ====
# 平移为 0 时两者相同；只要平移不为 0，T.T 就一定不等于 T 的逆
diff_inv = np.abs(inverse(T_base_cam) @ T_base_cam - np.eye(4)).max()
diff_t = np.abs(inverse(T_base_cam) - T_base_cam.T).max()
print("\n== 3. 便宜求逆 vs 转置 ==")
print(f"  max|inverse(T) @ T - I| = {diff_inv:.6g}")
print(f"  max|inverse(T) - T.T|   = {diff_t:.6g}")

预期输出（本机实测）：

== 1. R_y 的符号自检 ==
  R_y(90) @ (0,0,1)   = [1. 0. 0.]
  错符号版 @ (0,0,1)   = [-1.  0.  0.]

== 2. 下标消去 ==
  T_base_cam @ T_cam_obj = [1. 1. 0.]
  T_cam_base @ T_cam_obj = [0. 0. 0.]

== 3. 便宜求逆 vs 转置 ==
  max|inverse(T) @ T - I| = 0
  max|inverse(T) - T.T|   = 1

怎么确认自己跑对了

  1. 第 1 节两行必须是 [1. 0. 0.] 和 [-1. 0. 0.]。如果两行都是 [1. 0. 0.]，说明 wrong_y 的符号没改到，你验证的是同一个矩阵。
  2. 第 2 节第一行必须是 [1. 1. 0.]。如果是 [0. 0. 0.]，说明你把两个乘法写反了，或者 inverse 里的平移用了 -t。
  3. 第 3 节第二行必须是 1，不能是 0。如果是 0，说明 T_base_cam 的平移恰好为 0，这一项就没测到东西了。

八、常见坑

把 T_base_cam 写成 T_cam_base。程序不报错，输出是一个像模像样的坐标。本文算例里它给出 (0,0,0)，正好是基座原点。这类错误的唯一防线是每次写完乘法链，先用眼睛把下标首尾相接扫一遍。

inverse 里写成 -t 而不是 -Rᵀt。只有在旋转为单位阵时才对，而单位阵恰好是最容易碰到的情形（比如手算时随手把姿态设成 0），于是它在最需要验证的时候伪装成正确。

第二个杆用了 cos(θ2)。写出来的曲线依然光滑、依然像正解，只是形状错了。用 (π/4, π/2) 这一组自检能立刻抓到，因为正确答案的 x 分量恰好是 0。

把 np.cos(np.pi/2) 和 0 用 == 比较。它等于 6.123e-17。这一类判断要么用 np.allclose，要么先用 np.round 抹掉尾数。

用 det(R) = -1 的矩阵当旋转。它其实是一个镜像。det 为负通常意味着某个符号抄错，或者从别的书里抄了行向量约定。加上 det 检查几乎不花时间。
