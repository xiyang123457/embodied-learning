# W7 RL 报告：价值目标、终止语义与奖励设计

> 环境：4×4 网格，纯 NumPy  
> 复现命令：`./.venv/bin/python scripts/run_w7.py`  
> 原始结果：`outputs/w7/summary.csv`、`outputs/w7/vi_convergence.csv`、`outputs/w7/q_training_curves.csv`  
> 零基础讲义：`notes/W7_RL讲义.md`  
> 单元测试：`./.venv/bin/python -m pytest -q`，全仓 32 passed

## 摘要

1. 值迭代在固定协议下复现：不滑 **7 轮 / V(0)=0.950990**，滑面 **704 轮 / V(0)=0.542026**。
2. 不滑时 Q-learning 三个种子的 `Q0_max` 全部为 **0.950990**，纯贪心成功率 **500/500**；滑面 `Q0_max` 为 0.5798 / 0.4824 / 0.5169，均值 0.5264，与值迭代相差 **0.0157**。
3. 滑面三种子纯贪心成功率均为 **366/500 = 73.2%**，与值迭代策略在 H=100 的精确成功率 **74.0%** 接近。
4. 把 `truncated` 混成 `terminated` 后，滑面 `Q0` 均值从 **0.5664** 降到 **0.1684**，而 H=20 下的成功率没有同步归零，说明短程任务指标可能掩盖价值错误。
5. 错误奖励“变近就 +0.1”让训练不折扣回报从约 **0.4167** 升到 **1.1877**，但纯贪心成功率从 **52.8%** 降到 **0%**。回报只在本奖励函数内有意义，不能跨设计比较。

## 1. 环境与超参

### 1.1 网格与 MDP

```text
S  F  F  F        S=起点(0)   H=洞(5,7,11,12)   G=终点(15)
F  H  F  H        动作：0=左 1=下 2=右 3=上
F  F  F  H        奖励：进 G 得 +1，其余 0
H  F  F  G        终止：掉洞或到 G
```

| 要素 | 定义 |
|---|---|
| 状态 `S` | `0–15`，起点固定为 `0` |
| 动作 `A` | `0=左、1=下、2=右、3=上` |
| 转移 `P(s' ∣ s,a)` | 不滑时确定；滑时意图动作与两个垂直方向各 `1/3`，撞墙原地，重复落点概率累加 |
| 奖励 `r(s,a,s')` | 稀疏奖励：`s'=15` 时为 1，否则为 0 |
| 折扣 `γ` | 0.99 |
| 终止 | 洞和终点为 `terminated=True`；步数达到 H 为 `truncated=True` |

奖励由下一状态决定，因此价值更新使用：

```text
Q^*(s,a) = Σ_s' P(s' ∣ s,a) · [r(s,a,s') + γ · max_a' Q^*(s',a')]
```

### 1.2 实验协议

| 项 | 值 |
|---|---|
| 值迭代 | `V=0` 初始化，同步更新，`γ=0.99`，`tol=1e-12`，终止状态 V=0 |
| Q-learning | `α=0.1`，`γ=0.99`，`ε:1.0→0.05`，前 3600 局线性衰减，之后固定 0.05 |
| 训练量 | 每个实验、每个种子 6000 局；训练种子 0/1/2 |
| 纯贪心评估 | `ε=0`，测试种子 10000–10499，共 500 局；所有策略共享同一组测试种子 |
| D2 主实验 | H=100 |
| C1 终止语义 | H=20 |
| C2 奖励设计 | H=50 |

两个成功率口径必须分开：

- `train_success_last500`：训练最后 500 局，仍按 `ε-greedy` 行为策略统计，含探索；
- `greedy_success`：训练结束后 `ε=0`，独立测试种子上的任务成功率，是最终策略的主指标。

`Q0_max=Q[0].max()` 是价值诊断量，不是成功率。判断“到没到终点”只读取环境的成功条件，不读取训练奖励。

## 2. 有模型 vs 无模型

### 2.1 值迭代

![值迭代收敛曲线](../outputs/w7/vi_convergence.png)

| 冰面 | 收敛轮数 | `V(0)` |
|---|---:|---:|
| 不滑 | 7 | 0.9509900499 |
| 滑 | 704 | 0.5420259320 |

收敛轮数依赖初始化、同步/原地更新和 `tol`，不是脱离协议的常数。这里严格使用计划书协议。

![最优策略图](../outputs/w7/policies.png)

不滑最优策略是 6 步最短路径：**下、下、右、下、右、右**。滑面策略会绕开洞口。

**`V(0)` 不能读成成功率。** 不滑最短路径 6 步拿到奖励，`V(0)=0.99^5=0.950990`，但最优策略成功率是 100%。对滑面同一无限时域策略做精确评估：

| 评估上限 H | 折扣价值 `V(0)` | 不折扣成功率 |
|---:|---:|---:|
| 20 | 0.171030 | 0.195371 |
| 50 | 0.417377 | 0.535552 |
| 100 | 0.520260 | 0.740165 |

谈价值必须带 `γ`，谈成功率必须带 `H`。

### 2.2 Q-learning

![Q-learning 学习曲线](../outputs/w7/q_learning.png)

**不滑（H=100）**

| 种子 | `train_success_last500` | `greedy_success` | `Q0_max` | `|Q0-V*|` |
|---:|---:|---:|---:|---:|
| 0 | 0.952 | 500/500 = 1.000 | 0.950990 | ≈0 |
| 1 | 0.938 | 500/500 = 1.000 | 0.950990 | ≈0 |
| 2 | 0.954 | 500/500 = 1.000 | 0.950990 | ≈0 |

训练末 500 局约 95%，而纯贪心是 100%，差别来自训练时仍有 `ε=0.05` 的随机动作。**纯贪心 100% 不是“在训练集评估”的证据；在确定性网格上是正确结果。**

**滑面（H=100）**

| 种子 | `train_success_last500` | `greedy_success` | `Q0_max` | `|Q0-V*|` |
|---:|---:|---:|---:|---:|
| 0 | 0.506 | 366/500 = 0.732 | 0.5798 | 0.0378 |
| 1 | 0.466 | 366/500 = 0.732 | 0.4824 | 0.0596 |
| 2 | 0.508 | 366/500 = 0.732 | 0.5169 | 0.0252 |
| 均值 | 0.4933 | 0.732 | **0.5264** | **0.0157**（均值差） |

验收按计划书使用**三种子均值误差**：`|0.5264-0.542026|=0.0157<0.02`。逐种子误差没有都低于 0.02，因此原始值全部保留，不能挑种子。

滑面纯贪心成功率 **73.2%** 与值迭代策略的精确 100 步成功率 **74.0%** 接近，说明两条实现路径不仅价值接近，行为也基本一致。

**结论边界**：值迭代与 Q-learning 的一致性只是交叉证据，不是正确性证明。二者可能共享同一个环境、奖励或终止语义错误，所以还需要第 5 节的单元测试。

## 3. 终止语义

### 3.1 代码差异

```python
# 正确
done_for_bootstrap = terminated
target = r + gamma * Q[s2].max() * (1 - done_for_bootstrap)

# 错误
done = terminated or truncated
target = r + gamma * Q[s2].max() * (1 - done)
```

时间上限不是任务失败。H 步到了但还在非终止状态时，应当保留 `γ·max Q(s2)`。

### 3.2 实测结果（滑面，H=20，三种子）

| 处理方式 | `Q0_max`（种子 0/1/2） | 均值 | 与真值 0.542026 的均值误差 | `greedy_success@20`（0/1/2） | `train_success_last500`（0/1/2） |
|---|---|---:|---:|---|---|
| 正确（truncated 自举） | 0.5491 / 0.5882 / 0.5620 | **0.5664** | 0.0244 | 0.192 / 0.192 / 0.192 | 0.162 / 0.166 / 0.190 |
| 错误（混成 done） | 0.1409 / 0.2076 / 0.1566 | **0.1684** | **0.3737** | 0.138 / 0.180 / 0.104 | 0.160 / 0.168 / 0.164 |

错误组的价值均值只有真值的：

```text
0.1684 / 0.5420 = 31.1%
```

但错误组的短程成功率并没有归零：

- 训练末 500 局：正确 0.1727，错误 0.1640；
- 纯贪心 H=20：正确 0.1920，错误 0.1407。

这说明**短程成功率可能掩盖价值目标的破坏**，但不能反过来说“终止语义错误不会影响成功率”。500 局评估仍有采样波动，且不同错误种子从 0.104 到 0.180 不等。

### 3.3 为什么方向是低估

本网格奖励非负，正常 `Q≥0`。错误目标在时间截断时丢掉 `γ·max Q(s2)`，相当于删掉一个非负未来项，目标被压低；误差沿 backup 传播后形成系统性低估。

这个方向不能直接搬到 FetchReach：其奖励为失败 `-1`、成功 `0`，Q 通常非正；丢掉非正的 `γQ` 会让目标变得更不负，价值可能被抬高。**“截断要自举”是通用规则，“偏低还是偏高”取决于奖励符号。**

`|Q0-V*|/V* > 10%` 只能作为排查警报，不是充分判据。本次错误组误差约 69%，方向明确；但正确组也有种子误差 4.6%，不能单凭一个差值断定具体 bug。

## 4. 奖励设计

### 4.1 设计

- 正确奖励：进入终点 `+1`，其余 0；
- 错误奖励：Manhattan 距离变小 `+0.1`，其余 0；到终点仍终止，但不额外给奖励。

两组都使用滑面、H=50、6000 局 × 3 种子、正确的时间截断处理。成功判据只由环境决定，不读取训练奖励。

### 4.2 结果

| 奖励设计 | `greedy_success@50`（0/1/2） | `train_success_last500`（0/1/2） | 不折扣训练回报（0/1/2） | 折扣训练回报（0/1/2） | 平均步数 |
|---|---|---|---:|---:|---:|
| 正确（到终点 +1） | 0.528 / 0.528 / 0.528 | 0.410 / 0.418 / 0.422 | 0.410 / 0.418 / 0.422 | 0.3207 / 0.3313 / 0.3316 | 34.9 |
| 错误（变近就给 0.1） | 0 / 0 / 0 | 0.004 / 0.004 / 0.002 | 1.1750 / 1.1848 / 1.2032 | 0.9540 / 0.9615 / 0.9774 | 50.0 |

错误设计的训练不折扣回报均值约 **1.1877**，正确设计约 **0.4167**，数值上约为 2.85 倍。但这不是“错误设计性能更好”：

- 两组回报来自不同奖励函数，单位和行为分布不同，不能当作同一绩效指标比较倍数；
- 错误策略每次评估都跑满 50 步，在目标附近来回移动刷“变近”奖励；
- 它的任务成功率是 **0%**，正确策略是 **52.8%**。

这是最小规模的 reward hacking：智能体准确优化了写下来的奖励，却没有完成任务。

### 4.3 结论

1. 回报是优化信号，成功率是任务评价；两者不一致时，训练会优先提高实际写下的回报。
2. 任务验收以成功率为主要判据，同时报告回报用于解释训练行为。
3. 看到论文或项目自定义奖励时，要追问“有没有可能通过刷分获得高回报”。

## 6. 局限

1. 4×4 网格只有 16 个状态和确定性转移结构，结论不能直接外推到连续控制、真实机械臂或高维视觉输入。
2. 只测了一个错误奖励设计，不能代表所有 reward hacking 形态。
3. 只有表格 Q-learning，没有与 SARSA、策略梯度或深度 RL 对比。
4. 每个训练条件只有 3 个种子；滑面 `Q0` 的逐种子波动明显，均值验收通过不代表每个种子都准确。
5. C1 的价值破坏结论很强，但 H=20 的成功率差异有限；这正说明不能只看短程成功率，也不能把它推广成“成功率永远不变”。
6. 本周按要求不跑 FetchReach RL。关于 FetchReach 的终止语义结论只作为后续设计约束，没有在 MuJoCo 上重新验证。
7. 值迭代的 7/704 轮依赖 `V=0`、同步更新和 `tol=1e-12`；换协议后应报告实际轮数，而不是追求固定数字。
