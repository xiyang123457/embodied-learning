### 0.3 指标与评估协议（先定义，再看结果）

设 \(T\) 为从起点首次到达终点所经过的动作数。对策略 \(\pi\)：

\[
V^\pi(0)=\mathbb{E}\left[\gamma^{T-1}\mathbf{1}(T<\infty)\right],
\qquad
\mathrm{Success}_H^\pi=\Pr(T\le H).
\]

**价值是折扣回报，成功率是不折扣的“在 H 步内是否成功”。两者不是同一个量。**

本周所有实验必须区分以下指标：

| 指标 | 定义 | 用途 |
|---|---|---|
| `train_success_last500` | 训练最后 500 局，按训练时 ε-greedy 行为策略统计 | 看学习趋势，**不能代替最终评估** |
| `greedy_success` | 训练结束后 `ε=0`，在独立测试种子上跑 500 局 | **任务成功率的主口径** |
| `Q0_max` | `Q[0].max()` | 价值学习的诊断量，**不是成功率** |
| `avg_return` | 明确写“折扣”或“不折扣” | 优化信号诊断，不跨奖励函数比较 |

**固定评估协议：**

- 训练种子：`0 / 1 / 2`，每个训练过程独立初始化 `Q=0`；
- 独立测试种子：统一使用 `10000–10499`，共 500 局；
- 测试时 `ε=0`，动作取 `argmax(Q[s])`，并列时取编号最小的动作；
- 所有方法、所有训练种子面对同一组测试种子；
- 每个结果都保留原始逐种子值，图上可以画均值，但报告不能只写均值；
- 测试种子不得参与调参。

**每个实验的步数上限必须写死：**

| 实验 | 训练局数 | 每局上限 H | 训练种子 | 独立评估 |
|---|---:|---:|---|---|
| D2 值迭代 vs Q-learning | 6000 | 100 | 0/1/2 | 500 局纯贪心，H=100 |
| C1 终止语义 | 6000 | 20 | 0/1/2 | 500 局纯贪心，H=20 |
| C2 奖励设计 | 6000 | 50 | 0/1/2 | 500 局纯贪心，H=50 |

> `H` 是人为采集上限。到达上限且任务未真正结束时，`truncated=True`；洞和终点导致的结束才是 `terminated=True`。

## 1. 环境：4×4 网格，手写，不装依赖

```
S  F  F  F        S=起点(0)   H=洞(5,7,11,12)   G=终点(15)
F  H  F  H        动作：0=左 1=下 2=右 3=上
F  F  F  H        奖励：进 G 得 +1，其余 0
H  F  F  G        终止：掉洞或到 G
```

**五个 MDP 要素的定义要写清楚**，这是整周的地基：

| 符号 | 在这个网格里是什么 |
|---|---|
| 状态 `s` | 0–15 的格子编号 |
| 动作 `a` | 四个方向，0–3 |
| 转移 `P(s'\|s,a)` | 不滑时确定到一个格子；滑时 intended / 左垂直 / 右垂直各 1/3 |
| 奖励 `r(s,a,s')` | `1 if s' == 15 else 0`，奖励取决于**下一状态** |
| 折扣 `γ` | 0.99 |

> **冰面滑（`is_slippery`）是这个环境唯一有意思的地方**：你按“下”，有 1/3 概率实际往左、1/3 往右。
> 撞墙时原地不动；如果多个方向落到同一个格子，要把概率相加。  
> 打开它，最优策略会从“最短路径”变成“绕远但安全”，**这就是后面所有实验的对照组。**

## A · D1（1.5h）· MDP 与贝尔曼

### A1 先算折扣因子，别看公式（30min）

**不用看网格，先算一个无穷链**：每步都拿 1 分，折扣 γ，问总回报是多少。

```
G = 1 + γ + γ² + γ³ + ... = 1 / (1 − γ)
```

| γ | 总回报 `1/(1−γ)` | 含义 |
|---|---|---|
| 0 | **1.00** | 只看眼前这一步 |
| 0.9 | **10.00** | 看未来约 10 步 |
| 0.99 | **100.00** | 看未来约 100 步 |
| 0.999 | **1000.00** | 几乎不看折扣 |

**手算这四行，比读十遍「γ 控制远视程度」有用。** 有效视野大致是 `1/(1−γ)` 步。

> **γ 越接近 1，信用分配链越长**：一个动作的后果要更久以后才体现，采样型 RL 的方差和训练难度通常都会增加。指南第 17 周说「训练曲线不上升先查探索」，探索和折扣要一起看。

### A2 贝尔曼方程：一句话版本（20min）

**状态的价值 = 这一步的奖励 + 折扣后下一步的价值。**

本环境的奖励依赖下一状态，因此最优动作价值要写完整：

```text
Q*(s,a) = Σ_s' P(s'|s,a) · [ r(s,a,s') + γ · max_a' Q*(s',a') ]
V*(s)   = max_a Q*(s,a)
```

终止状态的价值固定为 0。

**注意两件事**：

1. 外面的 `max_a` 是“选最好的动作”，所以算出来的是**最优**价值 `V*`，不是某个策略的价值；
2. 里面的 `Σ P·[...]` 是“对下一步所有可能性取期望”，奖励也要放进期望里。

**如果去掉 `max_a`、固定一个策略 π**，就变成策略评估：

```text
Q^π(s,a) = Σ_s' P(s'|s,a) · [ r(s,a,s') + γ · Σ_a' π(a'|s') Q^π(s',a') ]
V^π(s)   = Σ_a π(a|s) Q^π(s,a)
```

值迭代和策略迭代的区别就在这一处，指南只要求理解，不要求都实现。

### A3 手算一个小例子（40min）

**三状态链**，`γ = 0.9`：

```
A --(r=0)--> B --(r=1)--> C(终止)
```

从 C 倒着算：

- `V(C) = 0`
- `V(B) = 1 + 0.9 × 0 = 1.00`
- `V(A) = 0 + 0.9 × 1.00 = 0.90`

**再加一条边**：`B --(r=0)--> A`，让 B 多一个选择：

- `V(B) = max( 1 + 0.9·V(C), 0 + 0.9·V(A) ) = max(1, 0.9·V(A))`
- 联立 `V(A) = 0.9·V(B)`，解得 `V(B) = 1.00, V(A) = 0.90`
- **结论**：多一条边，但那条边通向低价值状态，所以最优价值不变

> **手算这一步的目的**：让你在写代码之前就知道“值迭代就是反复套这个式子”。后面代码里的 `for k in range(iters)`，本质就是把 A3 的手算重复几百遍。

## B · D2（1.5h）· 值迭代 vs Q-learning

### B1 值迭代（有模型）40min

**前提**：你知道 `P(s'|s,a)`，也就是“每个动作会去哪”。

```python
V = np.zeros(N)
for k in range(iters):
    Q = np.zeros((N, A))
    for s in non_terminal_states:
        for a in range(A):
            # P[s,a,s2] 与 R[s,a,s2] 都是显式给出的
            Q[s, a] = np.sum(P[s, a, :] * (R[s, a, :] + gamma * V))
    V_new = Q.max(axis=1)
    V_new[terminal_states] = 0.0
    delta = np.abs(V_new - V).max()
    V = V_new
    if delta < tol:
        break
```

**复现协议**：`V=0` 初始化；同步更新（先算完整 `V_new`，再整体替换）；`γ=0.99`；`tol=1e-12`；终止状态强制置 0；双精度。

在这个协议下，独立复算结果：

| 冰面 | 收敛轮数 | `V(起点)` |
|---|---:|---:|
| 不滑 | **7 轮** | **0.9509900499** |
| 滑 | **704 轮** | **0.5420259320** |

> **收敛轮数依赖协议。** 改初始化、改成原地更新、改 `tol`，轮数都可能变化。报告要写清协议，不要把“7 / 704”当成脱离实现条件的常数。

**策略图（应能复现）**：

```
不滑：              滑：
↓ → ↓ ←            ← ↑ ↑ ↑
↓ H ↓ H            ← H ← H
→ ↓ ↓ H            ↑ ↓ ← H
H → → G            H → ↓ G
```

**这张图是这周第一个“看懂”的瞬间**：

- 不滑 → 走 6 步最短路径：**下、下、右、下、右、右**；
- 滑 → **绕远路避开洞**，宁可多走几步也不贴着洞走。

> ### 必须纠正的直觉
>
> **`V(起点)` 从 0.951 降到 0.542，不等于成功率从 95% 降到 54%。**
>
> 不滑时最短路径要 6 个动作，奖励在第 6 步才拿到，所以
> `V(0)=γ^5=0.99^5=0.9509900499`；但最优纯贪心策略的成功率是 **100%**。
>
> 滑面的 `0.542` 是折扣期望回报，不能直接读成“成功率 54%”。同一个 `γ=0.99` 最优策略在 `H=100` 时的精确成功率约为 **0.740**；若把 `γ` 改为 1 解无限时域，起点价值约 **0.8235**，这时它才等于最终成功概率。
>
> **这就是“优化信号”和“任务评价”的区别。** 指南 5.10 节说「奖励是优化信号，成功条件是任务评价规则」，在这里表现为：价值回答“回报折现后是多少”，成功率回答“给定步数内是否到达”。

### B2 表格 Q-learning（无模型）40min

**前提**：你**不知道** `P(s'|s,a)`，只能和环境交互。

```python
# 正确：时间截断仍自举，只有真正终止才切断
done_for_bootstrap = terminated
target = r + gamma * Q[s2].max() * (1 - done_for_bootstrap)
Q[s, a] += alpha * (target - Q[s, a])
```

**训练协议**：

| 项 | 值 |
|---|---|
| 训练局数 | 6000 |
| 训练种子 | 0 / 1 / 2 |
| `α` | 0.1 |
| `γ` | 0.99 |
| `ε` | 1.0 → 0.05，前 60%（3600 局）线性衰减，之后固定 0.05 |
| 每局上限 | H=100 |
| 初始 Q | 全 0 |
| 评估 | 训练后 `ε=0`，测试种子 10000–10499，500 局 |

**和值迭代的概念对比**：

| | 需要什么 | 一轮/一局更新什么 | 学到的东西 |
|---|---|---|---|
| 值迭代 | 完整转移模型 `P` | 扫全部 `(s,a)` | `V*(s)` |
| Q-learning | 只能采样 | 更新走过的 `(s,a)` | `Q*(s,a)` |

> **这就是“有模型”和“无模型”的分界**，也是整个 RL 领域最重要的一条线。
> 机器人上你几乎永远拿不到 `P`（真实世界的摩擦、接触、延迟都写不出来），
> **所以实际算法大多属于无模型一侧；Q-learning 只是其中一种，策略梯度和 actor-critic 也在这一侧。**

**原计划参考区间**（实现和随机数生成方式不同会有波动；按本计划固定协议重跑，不要求逐位命中）：

| 冰面 | `train_success_last500` | `Q0_max` | 值迭代 `V(0)` |
|---|---|---|---:|
| 不滑 | 0.938 / 0.954 / 0.960 | 0.951 / 0.951 / 0.951 | 0.9510 |
| 滑 | 0.520 / 0.560 / 0.540 | 0.572 / 0.506 / 0.559 | 0.5420 |

**必须新增纯贪心评估列**：

| 冰面 | 3 个训练种子的 `greedy_success`（H=100） | 3 个种子的 `Q0_max` | 值迭代 `V(0)` |
|---|---|---|---:|
| 不滑 | 预期 1.000 / 1.000 / 1.000 | 实跑填写 | 0.9510 |
| 滑 | 实跑填写（每局 500 次测试） | 实跑填写 | 0.5420 |

> 不滑网格的纯贪心策略 100% 成功是正常结果。训练末 500 局只有约 95%，是因为 `ε=0.05` 还在随机探索。

**交叉验证怎么看**：

1. 先比较**三种子均值**：滑面的参考均值约 `(0.572+0.506+0.559)/3=0.5457`，与 `0.5420` 相差约 `0.0037`；
2. 同时保留逐种子值：它们分别约为 0.030、0.036、0.017 的绝对误差，**不能假装三个种子都小于 0.02**；
3. 因此验收写成：**三种子均值误差 `<0.02`，逐种子全部报告**。如果坚持要求每个种子都 `<0.02`，就必须增加训练局数或降低方差，不能挑种子；
4. 这只说明两条实现路径给出了接近的价值估计，是**交叉证据，不是正确性证明**。共享的环境、奖励或终止语义错误仍可能让两边一起错，所以还要跑单元测试。

> 顺带一个观察：**滑面的方差明显更大**（`Q0_max` 的参考范围 0.506–0.572，而不滑三个种子基本重合）。冰面上每一步都随机，采样轨迹更散，Q 收敛更慢。这与值迭代需要 704 轮是同一类现象，但不要把它解释成“滑面一定需要 704 轮 Q-learning”。

### B3 一个必须回答的问题（10min）

> **`V(起点)` 和成功率是同一个东西吗？为什么不能直接拿两者比较？**

**答案：不是同一个量。**

- `V(0)` 是**折扣回报期望**：成功越早，价值越高；同样成功，6 步到达比 10 步到达价值更高；
- 成功率是**不折扣的事件概率**：只问在给定步数上限内有没有到达终点；
- 只有 `γ=1` 且无限时域等特定条件下，二者才可能对应；
- 不滑例子已经证明二者不同：`V(0)=0.95099`，但成功率是 100%；
- 滑面的 `0.542` 不能读成 54% 成功率。对同一个无限时域策略，改变评估上限 H，成功率会变，但无限时域 `V(0)` 不变。

对 `γ=0.99` 值迭代得到的策略做精确策略评估，可看到 H 的影响：

| 评估上限 H | 折扣价值 `V(0)` | 不折扣成功率 |
|---:|---:|---:|
| 20 | 0.171030 | 0.195371 |
| 50 | 0.417377 | 0.535552 |
| 100 | 0.520260 | 0.740165 |

> 表中是**同一个无限时域策略**在不同截止步数下的精确评估，不是训练曲线，也不是 Q-learning 输出。它只说明：**谈成功率必须带 H，谈价值必须带 γ。**

如果你发现 `Q0_max` 与值迭代差得很大，优先检查：终止语义、奖励位置、γ、H、探索是否充分、训练是否足够。**不能只凭一个差值就断定是哪一项错了。**

### C1 `terminated` 与 `truncated`：差一行代码（40min）

**两个词的区别**：

| | 含义 | 该不该自举 |
|---|---|---|
| `terminated=True` | **任务真的结束了**（掉洞、到终点、摔了） | **不该**。未来价值就是 0 |
| `truncated=True` | **时间到了**（H 步上限、外部中断） | **该**。任务没结束，只是这一局被截断 |

**代码上的差别就一处**：

```python
# 正确
done_for_bootstrap = terminated
target = r + gamma * Q[s2].max() * (1 - done_for_bootstrap)

# 错误（把两个混成一个 done）
done = terminated or truncated
target = r + gamma * Q[s2].max() * (1 - done)
```

**实验设计**：

| 项 | 值 |
|---|---|
| 环境 | 滑面 |
| 每局上限 | H=20 |
| 训练 | 6000 局 × 3 种子，其余超参与 B2 相同 |
| 对照 | 正确：只在 `terminated` 时截断；错误：`terminated or truncated` |
| 指标 | `Q0_max`（逐种子和均值）、`|Q0_max - V*(0)|`、`greedy_success@20`、`train_success_last500` |

本次实验记录表：

| 处理方式 | `Q0_max`（3 种子） | 均值误差 `|Q0-V*|` | `greedy_success@20`（3 种子） | `train_success_last500` |
|---|---|---:|---|---|
| **正确**（truncated 仍自举） | 实跑填写 | 实跑填写 | 实跑填写 | 实跑填写 |
| **错误**（混成一个 done） | 实跑填写 | 实跑填写 | 实跑填写 | 实跑填写 |

> 原计划记录过一组参考值：正确 `Q0≈0.520`，错误 `Q0≈0.171`，真值 `0.542`；当时末 500 局训练成功率约 0.134 与 0.146。  
> 这组数只作为 sanity 方向，**本次必须按固定协议重跑，逐种子保留；不要为了命中 0.520 或 0.171 调随机种子。**  
> 尤其注意：0.134 / 0.146 是**ε-greedy 训练行为**的成功率，不是纯贪心评估；不能拿它们证明“最终策略成功率没变”。

**为什么错误处理会伤害价值**：本网格奖励非负，`Q≥0`。时间截断时正确目标含有 `γ·max Q(s2)`，错误目标直接把它丢掉，于是目标被压低；不断传播后，价值出现系统性低估。

**结论必须这样写**：

> 在本实验中，错误地把 `truncated` 当成 `terminated` 会破坏价值目标，使 `Q0` 明显偏离值迭代真值；短程成功率可能暂时看不出明显差异，但这不能说明策略可靠。成功率差异要按独立纯贪心评估和多种子报告，不能根据原计划的一组数字概括成普遍规律。

**验证方法（写进报告）**：

1. 把 `Q0_max` 与值迭代的 `V*(0)=0.5420259` 对比；
2. 同时用纯贪心策略独立跑 500 局，报告 `greedy_success@20`；
3. **`|Q0 - V*| / V* > 10%` 只作为“优先排查”的警报，不是充分判据。** 它也可能来自训练不足、探索不足、奖励错位或评估口径不一致；
4. 做一个最小单测：同一转移下，`terminated=True` 的目标不含未来项，`truncated=True` 的目标仍含未来项。

> ### 这个坑为什么值钱
>
> 它不会让程序崩溃，也不一定马上让成功率归零，却会让价值函数悄悄偏离。  
> 后续做离线 RL、价值估计或模型式规划时，很多决策都以价值函数为前提。**前提错了，后面的分析就不可信，但表面上一切都能运行。**
>
> 同时要记住结论的方向依赖奖励：**正奖励网格里错误截断常导致低估；FetchReach 的负奖励下不能照搬这个方向。**

### C2 奖励设计：训练回报更高，任务成功率显著下降（50min）

指南第 17 周原文：「**把成功条件和奖励分开，至少测试一次错误奖励设计会产生怎样的行为**」。

**做一个错误奖励**：只要“离目标更近”就给 `+0.1`，走远不罚，到终点也不额外给。

```python
def reward_hacked(s, s2):
    return 0.1 if manhattan(s2) < manhattan(s) else 0.0
```

**固定协议**：

| 项 | 值 |
|---|---|
| 环境 | 滑面 |
| 每局上限 | H=50（两组完全一致） |
| 训练 | 6000 局 × 3 种子 |
| 正确奖励 | 进入终点 `+1`，其余 0 |
| 错误奖励 | Manhattan 距离变小 `+0.1`，其余 0；到终点仍终止，但不额外给奖励 |
| 成功判据 | 只由环境判断是否到达终点，**不读取训练奖励** |
| 评估 | 纯贪心 500 局，测试种子 10000–10499 |

**结果表必须包含逐种子值，不能只写均值**：

| 奖励设计 | `greedy_success@50`（3 种子） | `train_success_last500`（3 种子） | 不折扣训练回报（3 种子） | 折扣训练回报（3 种子） |
|---|---|---|---|---|
| 正确（到终点 +1） | 实跑填写 | 实跑填写 | 实跑填写 | 实跑填写 |
| 错误（变近就给 0.1） | 实跑填写 | 实跑填写 | 实跑填写 | 实跑填写 |

> **不要把两组回报算成一个“高 2.8 倍”的绩效倍数。** 两组回报来自不同奖励函数，数值单位和行为分布都不同，不能当作同一个任务指标比较。  
> 正确奖励下，一次成功的不折扣回报就是 1；错误奖励下，智能体可能反复“靠近—远离—再靠近”刷取多次 `+0.1`，训练回报自然可能更高。这个现象说明的是**优化目标与任务目标脱钩**，不是“错误设计表现更好”。

**它学到了什么**：智能体不必走到终点。只要在目标附近来回移动，就有机会不断拿到“变近”的奖励；而真正到达终点只结束回合。回合越长、刷分次数越多，训练回报越高，但任务成功率下降。

**必须写进报告的两句话**：

1. 回报是**优化信号**，成功率是**任务评价**；两者不一致时，训练会优先提高你实际写下的回报。
2. 因此**任务验收以成功率为主要判据，回报作为优化诊断同时报告**。不能只看回报宣布“学得好”，也不能完全不记录回报而失去解释训练行为的线索。

> 原计划既说“到终点也不额外给”，又说“真正走到终点只值 1 分”，这两句矛盾。本设计必须统一为：**成功本身没有额外奖励，只有“变近”的过程奖励。**

### C3 顺手回看 W5（10min）

**FetchReach 的 `terminated` 恒为 False**，所有回合都靠 50 步上限结束；W5 实测奖励是失败 `-1`、成功 `0`。

按 C1 的结论：

> **以后在 FetchReach 上做 RL，必须把 `truncated` 和 `terminated` 分开处理，而且 `truncated` 时仍然自举。否则价值目标会产生系统性偏差。**

但**不要照搬网格的偏差方向**。FetchReach 的奖励是非正的，`Q` 通常也非正；错误地去掉 `γQ` 相当于丢掉一个非正项，目标会变得更不负，价值可能被抬高（更接近 0），而不是“系统性偏低”。实际方向要按奖励符号和实现检查。

**这周不开 FetchReach 跑 RL**（时间不够，且指南第 18 周才要求），但这条结论要记下来。

## D · D4（1.5h）· PPO 与扩散概念

### D4.1 PPO 三件套（30min）· 只读不写

指南 5.10 节：「PPO 重点看**采样、优势估计与约束更新幅度**」「选择一个算法用成熟实现跑通，**不要求同时从零实现两者**」。

**只读三个概念，不实现**：

| 组件 | 一句话 | 解决什么 |
|---|---|---|
| **重要性采样** | 用旧策略采的数据估新策略的期望，靠比值 `π_new/π_old` 加权 | 让“一次采样多次更新”成立 |
| **clip** | 把重要性采样比值的目标项限制在 `[1−ε, 1+ε]` 附近 | 降低新旧策略差太远导致估计失效的风险 |
| **GAE** | 用多步的时序差分加权，平衡偏差与方差 | 优势函数 `A(s,a)` 估得更稳 |

**要能回答一句**：`clip` 在限制什么？

→ **限制新旧策略概率比值的贡献，避免一次更新把策略推得太远。** 它是 PPO 的启发式目标裁剪，不是严格的信赖域约束，也不能简单说成“梯度方向就一定不对”。

> **PPO 你只需要“能读懂”，不需要“能写”。** 你的目标是读 VLA 论文，不是做 RL 实验。指南自己写的也是「阅读基本结构」。

### D4.2 扩散 + 动作块 + 滚动时域（20min）· 指南第 16 周

**三个概念，一条链**：

| 概念 | 一句话 | 为什么具身智能需要它 |
|---|---|---|
| **扩散生成动作** | 从噪声开始，迭代去噪，最后得到一个动作序列 | 同一个观测下**可能有多个合理动作**，单点回归会平均成“都不像”的中间值 |
| **动作块**（action chunk） | 一次预测未来 N 步，不是一个动作 | 减少推理次数，动作更连贯 |
| **滚动时域**（receding horizon） | 预测 N 步，**只执行前 k 步**，然后重新观测 | 保留反馈能力，不至于一路开环跑到底 |

**要能回答一句**：预测 10 步，是不是意味着 10 步内不能再观察？

→ **不是**。预测长度和执行长度是两个独立设置，可以只执行 1–3 步就重新规划。

> 指南第 16 周原话：「**预测 10 步，不意味着必须不观察地执行全部 10 步**；每次执行多少步是系统设置。」
> 这句话以后读 ACT / Diffusion Policy / π0 都会反复出现。

## F · 卡点预案

| 卡在哪 | 处理 |
|---|---|
| 值迭代不收敛 / V 全是 0 | 检查终止状态有没有强制置 0；洞和终点必须置 0，否则价值会一直涨 |
| 值迭代收敛轮数不是 7 / 704 | 先核对初始化、同步/原地更新、`tol` 和终止状态处理。轮数依赖协议，不是固定常数；`tol=1e-9` 可作敏感性检查 |
| 滑面的策略图看起来在乱走 | 冰面上多个动作价值接近，argmax 会跳。**看整体趋势，不盯单格** |
| Q-learning 成功率一直 0 | ① ε 衰减太快，探索不足；② `Q[s2].max()` 里 `s2` 用了 `s`；③ 奖励符号反了；④ 成功和洞是否被正确标记为 `terminated=True`，终止后是否仍错误地继续更新 |
| Q-learning 纯贪心成功率 100% | **不滑网格上这是正常结果**，不是“一定在训练集评估”。先确认测试种子独立、`ε=0`、H 明确；滑面再分析 |
| 学到的 `Q0` 和值迭代差很多 | 先查终止语义和奖励位置，再查 γ、H、探索、训练量。`>10%` 只是排查警报，不是充分结论 |
| 奖励实验里两种设计回报一样 | 奖励函数要单独传进训练循环，环境转移和成功判据不能一起改 |
| 奖励实验成功率无法复现旧数字 | 旧数字可能来自不同 RNG/H 协议。先固定本计划协议，报告实际逐种子值，不为命中旧数字挑种子 |
| 表格 Q-learning 收敛太慢 | 4×4 不滑通常几百局，滑面需要更多。**别用 1000 局判断“学不会”**；先看训练曲线趋势 |
| 时间只给到 3h | 保 **值迭代 + Q-learning 交叉验证 + 终止语义对照**。奖励实验顺延到 W8 开头 |
